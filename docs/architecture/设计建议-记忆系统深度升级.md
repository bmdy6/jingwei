# 记忆系统：当前实现与后续方向

本页保留早期记忆设计的动机，并按当前代码更新边界。实现以 `agent/memory/`、`agent/session/` 和测试为准。

## 当前实现

会话消息写入 JSONL，SQLite 索引用于跨会话搜索；长期知识条目保存在 `knowledge_items`，向量保存在 `ki_embeddings`。FTS5 和本地 m3e-base 向量共同参与召回，检索结果经排序后按需进入提示词。SQLite 构建缺少 FTS5 时使用普通表和关键词匹配。

本地向量模式要求预先准备模型文件。路径不存在或模型加载失败时返回零向量，保留关键词检索。云端 embedding 是可选配置，会产生额外请求。

会话后流程尝试从反馈和偏好中提炼规则，写入 `agent_memory/skills/自学习技能/规则与偏好.md`，随后注入系统提示词。模型提炼可能出错，规则需要定期复核。项目不包含原作者的记忆、用户画像或会话数据。

`ContextCompressor` 当前只估算 Token，自动上下文压缩已停用。不要把早期压缩方案当作现有能力。

## 设计取舍

- JSONL 保留会话原文，SQLite 支持结构化查询与全文检索。两份数据需要分别管理和备份。
- 本地模型降低向量请求对在线服务的依赖，但需模型文件、内存和加载时间。
- 按需注入记忆减少提示词体积，但检索遗漏仍可能发生。
- 反馈提炼提供跨会话约束，无法保证输出总能遵守这些约束。

## 后续可验证的方向

1. 用固定问题集测量关键词、向量与混合召回的差异。
2. 给提炼规则保留来源和撤销方式，验证冲突与过期规则的处理。
3. 在压缩或归档前验证重要事实是否已保存；当前版本不承诺该流程。
